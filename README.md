# Pechnik.su — Astro Starter

Frontend-инфраструктура для поэтапной разработки многостраничного магазина и переноса статического HTML в CMS. Главная страница сейчас — технический UI Kit, а не дизайн магазина.

## Требования и запуск

Node.js **22.12.0+**, рекомендуется LTS 24 (`.nvmrc`), npm 10+. Проверено на Node 24.14.0 / npm 11.9.0, Windows.

```sh
npm ci
npm run dev
```

Dev-сервер: `http://localhost:4321`. Поддерживаются Astro HMR, SCSS и обновление SVG webfont.

```sh
npm run check
npm run build
npm run preview
```

`check` проверяет Astro и TypeScript. `build` собирает статический сайт, выпускает два CSS-файла, переключает HTML на минифицированный вариант и проверяет локальные ресурсы. `preview` показывает уже собранный `dist/` по HTTP.

Дополнительные команды:

- `npm run verify:dist` — повторная структурная проверка существующего `dist/`.
- `npm run fonts:prepare` — повторно копирует выбранные WOFF2 из установленного `@fontsource/manrope` и лицензию. Обычно не нужна: реальные файлы уже находятся в исходниках. При изменении локальных шрифтов сначала проверьте, нужно ли их перезаписывать этой командой.

## Astro-компоненты и страницы

Имена компонентов — PascalCase, одна ответственность на компонент. Типизируйте `Props`, передавайте данные через props и slots. Данные товаров в будущем размещайте отдельно от разметки. Используйте семантические элементы и нативные возможности HTML до добавления JS.

```astro
---
import BaseLayout from '../layouts/BaseLayout.astro';
---
<BaseLayout title="Название — Pechnik.su" description="Описание страницы">
  <section aria-labelledby="heading">
    <h1 id="heading">Название</h1>
  </section>
</BaseLayout>
```

`BaseLayout` имеет основной slot, `header`, `footer`, `head`. Внутри уже есть `<main id="main">`, второй main добавлять не нужно. Новые страницы создаются в `src/pages/`; Astro выпускает для них обычные HTML-файлы. SSR, клиентские islands и runtime-фреймворки не используются.

Для favicon пока нет отдельного ресурса. Когда он появится в `public/favicon/`, добавьте `<link rel="icon">` в BaseLayout с учётом `import.meta.env.BASE_URL`.

## SCSS и дизайн-токены

Собственные модули подключайте в `main.scss` через `@use`; общие API экспортируйте через `@forward`. Используйте БЭМ, неглубокую вложенность, токены вместо случайных значений. Не добавляйте глобальные стили отдельно в каждой странице и не импортируйте SCSS из динамических JS-модулей: весь CSS должен оставаться в общем графе.

```scss
@use '../abstracts' as a;
.feature { padding: var(--space-4); color: var(--color-text); }
@include a.up(lg) { .feature { padding: var(--space-6); } }
```

`abstracts/_tokens.scss` определяет палитру, размеры шрифтов, line-height, интервалы, радиусы, тени, длительности, слои и layout. Ключевые значения экспортируются в `:root`. Тёмный `--color-action: #ab4800` используется для читаемых ссылок и кнопок с белым текстом; исходный `--color-accent` сохранён для акцентов.

Логотип имеет viewBox `4.5 0.83333 98.375 98.33334`, почти квадратный. Используется как локальный `<img>` с `height: auto`, исходные контуры и пропорции сохранены. Его цвета выделены в `brand-*` токены, общая предварительная палитра сохранена.

### Bootstrap

Все legacy `@import` изолированы в `vendors/_bootstrap.scss`, `node_modules` не меняется. Включены только functions, variables, maps, mixins, Reboot, containers, grid, utilities API. Визуальные компоненты и Bootstrap JS не подключены.

Whitelist utilities: `display`, `flex-direction`, `justify-content`, `align-items`, `order` (с предусмотренной Bootstrap адаптивностью). Нет глобального набора spacing/color utilities. Сетка — 12 колонок, стандартные классы `.container`, `.container-fluid`, `.row`, `.col-*` и адаптивные варианты.

Breakpoints и контейнеры централизованы в `abstracts/_grid-settings.scss`: 576/768/992/1200/1400 px, контейнеры 540/720/960/1140/1320 px, gutter 1.5rem. `abstracts/_breakpoints.scss` предоставляет фасад над Bootstrap mixins, не выпуская CSS сетки повторно.

## Inline SVG

```astro
<Icon name="search" size={24} />
<Icon name="cart" size={24} class="header__icon" />
<Icon name="cart" decorative={false} label="Корзина" />
```

Добавьте SVG в `src/assets/icons/inline/`, имя файла становится именем иконки. Нужен `viewBox` в двойных кавычках; для монохромных контуров используйте `currentColor`. Компонент вставляет содержимое на этапе сборки, без сетевых запросов. Неизвестное имя и содержательный режим без label вызывают ошибку сборки.

Декоративная иконка скрывается от скринридера. Кнопке с одной декоративной иконкой задайте собственный `aria-label`. Каталог должен содержать только доверенные SVG разработчика: `set:html` не является санитайзером. Избегайте script, внешних ссылок и повторяющихся id для градиентов/масок.

## SVG webfont

Добавьте монохромный SVG с замкнутыми заполненными контурами в `src/assets/icons/font/`. Stroke-only контуры перед этим преобразуйте в заливки. Плагин отслеживает файлы, генерирует WOFF2/WOFF и виртуальный CSS:

```html
<i class="p-icon p-icon-search" aria-hidden="true"></i>
```

Имя файла определяет класс. Основной импорт `virtual:vite-svg-2-webfont.css` находится в BaseLayout и попадает в общий CSS. Для существующих иконок codepoints зафиксированы в `astro.config.mjs`; новым иконкам назначайте уникальные значения там же, если требуется стабильная кодировка. Не привязывайтесь к автоматически назначенным символам в CMS — используйте классы. TTF/EOT/SVG-font не выпускаются.

## Локальные шрифты

Manrope распространяется по OFL-1.1, текст лицензии — `src/assets/fonts/manrope/OFL.txt`. Используются реальные файлы весов 300/400/600/700, отдельно latin и cyrillic, `font-display: swap`, `unicode-range`. Курсив не объявлен. Расширенная кириллица, греческие и другие дополнительные наборы не включены.

Для добавления гарнитуры положите реальные WOFF2 и лицензию в `src/assets/fonts/`, объявите только имеющиеся веса в `base/_fonts.scss`, обновите токен семейства. Учитывайте покрытие символов и ограничения лицензии. Внешних font CDN нет.

## JavaScript и библиотеки

`main.ts` проверяет `data-*` и динамически импортирует независимые модули. Нет обращений к DOM во frontmatter и нет глобальных переменных приложения.

- `[data-fancybox]` — один делегированный `Fancybox.bind`, только при наличии ссылок. Ссылка без JS открывает исходное изображение.
- `[data-demo-slider]` — независимые экземпляры Swiper в WeakMap. Модули: Navigation, Parallax, A11y; стили core/A11y/Parallax. Navigation использует собственные кнопки. Учитывается reduced motion.
- `[data-demo-alert]` — обработчики демонстрации с WeakSet. SweetAlert2 загружается только при вызове `notify(options)`. Используется JS-сборка без внедрения CSS: CSS подключён отдельно.

```ts
import { notify } from './modules/alerts';
await notify({ icon: 'success', title: 'Готово', text: 'Операция выполнена' });
```

Новые библиотеки подключайте аналогично: проверка DOM → динамический импорт, защита от повторной инициализации, локальный контекст элементов, CSS через общую систему. Не импортируйте bundle Swiper, если достаточно отдельных модулей. Для пользовательского текста используйте текстовые параметры уведомления, не HTML.

## Production CSS и JS

Astro: `output: 'static'`, `inlineStylesheets: 'never'`. Vite: `cssCodeSplit: false`, `cssMinify: false`, `assetsInlineLimit: 0`. Autoprefixer берёт targets из `browserslist` в package.json (современные браузеры, без IE/Opera Mini).

1. Vite собирает единый `dist/assets/css/style.css`, включая CSS реально подключённых библиотек и webfont.
2. `scripts/finalize-css.mjs` минифицирует его через PostCSS/cssnano 7 в соседний `style.min.css` и меняет ссылку в HTML.
3. `scripts/verify-dist.mjs` проверяет два CSS-файла, шрифты и ссылки HTML/CSS, базовые ES-импорты клиентских чанков.

cssnano добавлен как dev-инструмент для двух обязательных CSS-вариантов. Ветка 9 требует более новую Node, поэтому выбрана совместимая 7.1.9. Загружайте **только один** stylesheet: production HTML использует `style.min.css`. CSS не нужно подключать повторно из модулей.

JS минифицирует Vite. Имена клиентских чанков и шрифтов хешируются; динамические библиотеки остаются отдельными чанками. Все шрифты и SVG-ресурсы выпускаются файлами, без data URI. Собственные inline SVG, естественно, остаются в HTML.

## Перенос в CMS

1. Скопируйте **весь** `dist/assets/` с сохранением структуры, включая динамические JS-чанки и шрифты, а также нужные `dist/images/`.
2. Перенесите HTML из `dist/index.html` в шаблон CMS, разделив header/main/footer по правилам CMS.
3. Подключите `assets/css/style.min.css` один раз. `style.css` — читаемый альтернативный вариант; для отображения он не обязателен.
4. Сохраните `<script type="module" src="…">` из сгенерированного HTML. Не переименовывайте отдельные JS-файлы: они ссылаются друг на друга.
5. Заменяйте демонстрационные данные данными CMS, сохраняя классы, доступные имена и `data-*` интерфейс.
6. По умолчанию сайт размещается от корня домена (`/assets/`, `/images/`). Если CMS размещает ресурсы в другом каталоге, согласуйте пути до переноса. Для размещения всего сайта под префиксом задайте `base` в Astro и проверьте ссылки после сборки; автоматический `verify:dist` сейчас рассчитан на корневое размещение.

Astro и Node.js на production-сервере не нужны. Нужен обычный HTTP-сервер с MIME для ES modules, SVG и шрифтов. Открытие HTML через `file://` не является поддерживаемым способом проверки. Для стабильного имени CSS учитывайте сброс кеша при деплое; хешированные ресурсы можно кешировать длительно. Не смешивайте чанки из разных сборок.

## Архитектурные решения

- **Статический Astro (принято):** компоненты компилируются в переносимый HTML. Компромисс — динамические данные и бизнес-логика будут ответственностью CMS.
- **Общий CSS (принято):** удобный перенос, единый порядок стилей. Компромисс — библиотечный CSS доступен на всех страницах; при росте проекта пересмотреть необходимость библиотек, сохраняя требование единого stylesheet.
- **Lazy JS (принято):** библиотеки не загружаются на страницах без соответствующего DOM, SweetAlert2 — до первого действия. Компромисс — при первом действии возможна загрузка чанка.
- **Два каталога иконок (принято):** независимые требования к SVG, без неявной трансформации inline-графики в glyphs. Компромисс — одинаковые иконки поддерживаются в двух исходниках.
- **Legacy Bootstrap boundary (принято):** совместимость с обязательной версией 5.2, собственный код на модульном Sass. Компромисс — предупреждения о deprecated `@import` до смены Bootstrap.

## Проверки и ограничения

Выполнены `npm run check` (0 ошибок/предупреждений) и `npm run build`; проверены две CSS-версии, генерация WOFF2/WOFF, локальные ссылки и статический HTML. Browser smoke-проверка выполняется отдельно от зависимостей проекта, через временный Playwright/Chromium на обычном HTTP-сервере: переключение Swiper и Parallax, открытие/закрытие Fancybox, SweetAlert2, локальные шрифты, ширины 375/768/1440 и browser errors. Это не полная кроссбраузерная сертификация и не проверка HTML внешним валидатором.

Известные ограничения:

- Bootstrap 5.2 вызывает Sass deprecation warnings на `@import`. Сборка успешна; собственные стили используют `@use`/`@forward`, исключение — явно выделенный vendor-файл. `quietDeps` не подавляет предупреждения самой точки импорта.
- `npm audit` на момент установки сообщает 3 уязвимых пакета: Astro (critical), sharp (high), esbuild (low). Предлагаемое npm исправление требует Astro 7, что выходит за заданный стек. Автоматический force-update не применялся. Здесь нет SSR, image optimization, MDX и View Transitions, но это не означает устранение уязвимостей инструментария. Перед обновлением стека повторно оцените advisories и совместимость.
- Базовый путь проверки сборки — корень домена. Имена/количество CSS верифицируются строго; при намеренном изменении стратегии обновите проверку.
- Favicon пока не создан: исходного ресурса нет. CMS-интеграция, каталог, корзина и серверная логика — последующие этапы.
- Fancybox имеет собственные условия лицензирования; условия коммерческого использования доступны на сайте Fancyapps.
