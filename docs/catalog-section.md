# Страница раздела каталога

Маршрут: `/category/`, исходник — `src/pages/category/index.astro`. После `npm run build` создаётся отдельный готовый HTML-файл `dist/category/index.html` для переноса в CMS. Страница полностью генерируется при сборке (`output: 'static'`), серверный рендеринг не используется. При переносе вместе с HTML нужны общие ресурсы `dist/assets/`, `dist/css/` и `dist/js/` с сохранением путей.

Используется существующий `CatalogLayout` без изменений: он выводит единственный H1, Breadcrumbs, sidebar и основной slot. Навигация создаётся из `showcaseData` точно так же, как на `/catalog/`. Для промежуточного раздела «Чугунное и печное литьё» маршрут пока не существует, поэтому Breadcrumbs выводит текст без выдуманной ссылки.

## Компоненты и данные

- `CatalogNotices.astro`: необязательный `items: CatalogNotice[]`. Сообщение — строка либо массив `{ text: string, strong?: boolean }`. Astro экранирует текст; произвольный HTML не поддерживается. Отсутствующие, пустые и состоящие из пробелов сообщения не создают контейнеров.
- `CatalogSubcategories.astro`: необязательный `items: CatalogSubcategory[]` с полями `name`, `img`, `url`. Один элемент списка содержит одну ссылку на всю карточку. Пустой массив или отсутствие prop не создаёт разметки.
- `src/data/rubtsovsk-casting.ts`: 12 категорий в исходном порядке с исходными путями и `url: '#'`; единственное релевантное уведомление о стоимости и наличии.
- `src/types/catalog-section.ts`: типы данных для замены источника на CMS.
- `_catalog-section.scss`: изолированные БЭМ-классы через общий `main.scss`, существующие токены и breakpoint mixins. Глобальные правила и существующие компоненты не меняются.

Содержимое раздела находится в default slot страницы, независимо от наличия уведомлений и вложенных категорий.

После вложенных категорий подключён `CatalogSorting`: [разметка, адаптивность, проверки и контракт CMS](catalog-sorting.md). Панель пока не управляет товарами.

После товарной сетки подключён общий [Pagenavigation](pagenavigation.md): демонстрация первой страницы из пяти, без переключения товаров.

## Товарная сетка

После панели сортировки выводится `.catalog-products`: первые 32 записи из 68 в `assets/products.json`, статически импортированные в страницу и ограниченные `slice(0, 32)`. Порядок JSON сохранён, исходный файл не меняется. На уровне страницы пять числовых флагов приводятся через существующий `normalizeFlag` к типам `ProductItem`; остальные поля передаются без изменений. Каждая запись выводится циклом через существующий `<ProductCard product={product} />`. Список имеет доступное название и роли list/listitem; дополнительных заголовков нет.

`src/styles/components/_catalog-products.scss` подключён в общем `main.scss` и задаёт только внешнюю CSS Grid-сетку: до 576 px — одна колонка, от 576 px — две, от 992 px — три, от 1200 px — строго четыре. При 1440 px 32 карточки образуют восемь рядов. На узких мобильных экранах одна колонка сохраняет неизменённые количество и кнопку покупки в строке ProductCard. Интервалы используют `--space-3`, от 768 px — `--space-4`. Рамки, outline и box-shadow внешнему контейнеру не добавляются; границы карточек сохранены. Внутренние стили и API ProductCard не менялись.

Сортировка и количество в панели не связаны со списком; нет фильтрации, пагинации, новых скриптов или зависимостей. Штатный модуль ProductCard по-прежнему подключается существующим main.ts при обнаружении карточек. При переносе в CMS заменить источник данных, сохранить API карточки и классы сетки. В исходных данных есть печи разных моделей, а не только литьё; список намеренно выводится без фильтрации. URL товаров `#` сохраняет существующее отключённое состояние ссылок ProductCard.

Проверки товарного этапа:

- `npm run check`: 0 ошибок, 0 предупреждений, одна прежняя подсказка в тесте featured products. Отдельных lint/typecheck-команд нет.
- `npm run build`: успешно, пять страниц, два CSS, 277 ссылок на ресурсы. Существующие Sass-предупреждения Bootstrap и отсутствующее изображение `assets/images/main_XEWTaZkyPl.jpg` на главной; на `/category/` все 32 изображения разрешены.
- `scripts/test-catalog-section-browser.mjs` на preview: Chrome с отключённым JS; число и точный порядок ID/названий из JSON, загрузка всех изображений, колонки 4/3/2/1/1 на 1440/1024/768/390/320 px, восемь desktop-рядов, равные ширины, границы карточек, отсутствие внешней рамки и переполнения страницы/элементов покупки. Существующие проверки категорий, уведомлений, панели сортировки и клавиатурного фокуса также прошли.
- Снимки `artifacts/catalog-section/products-*.png` и JSON-отчёт сохранены; визуально просмотрены 1440, 768 и 390 px. Firefox/Safari не проверялись.

## Изображения и доступность

Все 12 файлов найдены в корневом `assets/images/categories/`, не в `public`. `import.meta.glob` получает ImageMetadata и Vite выпускает браузерные URL `/assets/...` без копирования исходников. У изображений реальные width/height, lazy loading, async decoding и object-fit contain. Пустой alt исключает повтор названия той же ссылки скринридером. При неизвестном пути отображается текст «Изображение недоступно» вместо сломанного img.

Список семантический, названия переносятся; hover и focus подчёркивают название. Используется существующий focus-visible с отступом внутрь карточки и глобальное правило reduced motion. Клиентский JS не добавлен.

Фон ссылки при наведении не меняется. Класс `shine` на области изображения добавляет блик длительностью 0,4 с при наведении на всю ссылку или её клавиатурном фокусе. Общие стили эффекта подключены из `utils/_shine.scss`; при `prefers-reduced-motion: reduce` блик отключён.

## Адаптивность

- До 768 px: компактные горизонтальные строки с областью изображения 48 × 48 px; sidebar скрывается существующим layout.
- 768–991 px: две колонки с изображениями сверху, sidebar 224 px.
- 992–1199 px: три колонки.
- От 1200 px: четыре колонки, sidebar 240 px.

Desktop-область изображения ограничена 128 × 128 px; высота строки определяется содержимым, ссылки занимают всю карточку.
