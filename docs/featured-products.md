## Props

| Prop | Тип / default | Поведение |
| --- | --- | --- |
| title | string / «Избранные товары» | H2 и доступное имя навигации |
| categories | FeaturedCategory[] | Исходный порядок категорий и товаров |
| maxProducts | number / 10 | Целое ограничение 0–10; неконечное значение → 10; исходный массив не изменяется |
| initialTab | number / 0 | Индекс с нуля; некорректный индекс → первая категория |

Пустой массив не создаёт секцию. Пустая категория выводит сообщение «В этой категории пока нет товаров». Несколько экземпляров получают UUID в ID кнопок, панелей и заголовков.

## Переключение и доступность

Проверка DOM в main.ts → динамический импорт → initFeaturedProductsTabs. WeakSet предотвращает повторную инициализацию. Функция принимает необязательный root, включая корень самого компонента.

Клик и нативные Enter/Space активируют кнопку. ArrowLeft/ArrowRight циклически переключают вкладки с автоматической активацией; Home/End выбирают крайние вкладки. tabindex=0 получает только активная кнопка, остальные — -1. Обновляются aria-selected, hidden, .active и .behold. Связи tablist/tab/tabpanel заданы через уникальные aria-controls/aria-labelledby. Панель доступна для фокуса; фокус на первую карточку не переносится.

Все товары сформированы Astro. Смена видимости не пересоздаёт DOM, не меняет значения quantity и не требует localStorage. Модуль ProductCard находит формы и в скрытых панелях: его инициализация не зависит от размеров/видимости. hidden исключает неактивное содержимое из клавиатурной навигации.

Начальная панель видна в HTML до JS, остальные имеют hidden. В noscript встроенное правило показывает все панели и их заголовки, скрывает неработающую навигацию и отключает анимацию. Карточки не дублируются. При ошибке загрузки JS с включённым JS noscript не применяется — это ограничение выбранного fallback.

## Прокрутка, анимация и сетка

Навигация использует flex-wrap: nowrap, white-space: nowrap, overflow-x: auto. Сохраняется тонкая видимая полоса прокрутки. Внутренние отступы вмещают focus outline. Положение выбранной кнопки сравнивается с границами навигации; scrollBy перемещает только навигацию по горизонтали. Фокус устанавливается с preventScroll. При reduced motion используется мгновенная прокрутка.

Только .featured-products__panel.behold получает opacity-анимацию 0→1 на 0,5 с ease. При reduced motion она отключена. hidden отдельно сохраняет display:none. Глобальных правил .active/.behold нет.

| Viewport | Колонки |
| --- | --- |
| <768px (включая 360/390/576) | 2 |
| 768–991px | 3 |
| 992–1199px (включая 1024) | 4 |
| ≥1200px (включая 1440/1920) | 5 |

Использованы стандартный .container и Bootstrap breakpoint mixins. При 1200px его ширина 1140px, доступная ширина сетки 1116px, четыре промежутка по 16px: ширина карточки около 210,4px при базовом шрифте 16px. minmax(0,1fr) сохраняет пять колонок. Внутри существующего container product-card локальная query до 15rem ставит кнопку под счётчик, уменьшает отступы до токена space-2 и разрешает перенос наличия/скидки. Шрифты и все элементы покупки сохраняются; цены используют штатный flex-wrap ProductCard.

Высота панелей естественная: только активная сетка участвует в потоке, число рядов определяется числом товаров. Нет фиксированной высоты, общего min-height, пустых карточек и вычислений высоты в JS. Неполный ряд сохраняет ширину пятиколоночной сетки.

## Проблемы исходных данных

- id=123, «Дверка ВЕЗУВИЙ печная ДТ-4 Антрацит (В)»: цена `5 3000` сохранена буквально. ProductCard принимает непустую строку, не вычисляет цену; покупка определяется его существующим canBuy/hasPrice.
- id=2: путь `assets/images/products/ETNA_18ЗК_new_setka.jpg` отличается регистром от существующего `ETNA_18ЗК_New_setka.jpg`. Точное разрешение изображений ProductCard не находит запись, выводит штатную заглушку.
- id=123: `assets/images/main_XEWTaZkyPl.jpg` не разрешается существующим ProductCard, также выводится заглушка.
- Ссылки `#` сохраняют согласованное ProductCard поведение недоступной ссылки. Цены, скидки, порядок и коммерческие флаги не исправлялись.

## Интеграция с 1С-Битрикс

Передать названия, порядок и массивы товаров через props либо заменить статические циклы серверными, сохранив HTML-контракт. Для каждого экземпляра генерировать уникальные ID, сохранять role, ARIA, hidden, data-атрибуты и классы. Исходные данные CMS должны соответствовать ProductItem, включая boolean/0/1, проверенные URL изображений и готовые форматированные цены.

Перенести общий CSS и все связанные JS-чанки одной сборки. Tabs не зависит от JSON или инфоблока, PHP/API/AJAX в реализации нет. Реальное добавление в корзину остаётся отдельной задачей интеграции существующего ProductCard: его product-card:demo-submit — демонстрационное событие, а не подтверждение покупки.
