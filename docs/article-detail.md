# Детальная статья

Демонстрация: `/article/demo-article/` (раздел списка — `/article/`).
`ArticleDetail.astro` использует неизменённый CatalogLayout: один H1 и Breadcrumbs,
общий Header/Footer, существующий Sidebar, без фильтра. Меню передаётся через
navigation, как на странице списка. Sidebar скрыт до md.

## API

Обязательные props: title, description, breadcrumbs, navigation.
Изображение: `image={{ src, alt, width, height }}`. Расположение:
`imagePosition="wide"` (по умолчанию), `"left"` или `"right"`.
Для компактного варианта можно импортировать `assets/images/articles/1_small.jpg`.
Для отсутствия изображения не передавайте image. Для отсутствия анонса не
передавайте summary (пустая строка также скрывает блок). Пустые обёртки не выводятся.
Анонс при float располагается рядом с изображением; текст продолжается под ним.
До 768 px float отключён. Родитель flow-root удерживает плавающее изображение.

Тело передавайте обычным HTML через default slot либо строкой `content`.
При передаче content он имеет приоритет над slot. Строка должна приходить из
доверенного редактора и проходить очистку в CMS: Astro set:html её не очищает.
H1 уже формируется Layout; внутри тела используйте H2–H4.

## HTML редактора

Все стили ограничены .article-content / .article-detail / .article-gallery.
Абзацам, спискам (включая вложенные), цитатам, ссылкам, figure/figcaption и
таблицам дополнительные классы не нужны. Даже голый table прокручивается
горизонтально внутри собственной области. Для доступности широкой таблицы
можно добавить `tabindex="0"` и `aria-label` самому table.
Iframe с title получает ширину 100% и aspect-ratio 16:9 без собственного плеера.
В демонстрации внешний YouTube iframe; доступность сервиса зависит от сети.

Ряды фотографий:

```html
<div class="article-content__images article-content__images--2">
  <figure>
    <a href="/full.jpg" data-fancybox="article-photos"
       class="article-content__image-link" aria-label="Открыть фото: печь в гостиной">
      <img src="/preview.jpg" alt="Печь в гостиной" width="800" height="600" loading="lazy">
    </a>
    <figcaption>Печь в гостиной</figcaption>
  </figure>
</div>
```

Модификаторы --1, --2, --3 задают число колонок. На mobile одна колонка;
на tablet тройной ряд становится двойным. Для фото без подписей используйте
div вместо figure; без Fancybox уберите ссылку. Пропорции изображений сохраняются.
У изображений ниже первого экрана задавайте lazy и размеры.
Одинаковый data-fancybox объединяет изображения, разные значения разделяют группы.
Используется уже установленный Fancybox и существующий делегированный обработчик.
Новых JS-модулей и зависимостей нет. Hover ограничен устройствами с hover,
при reduced motion масштабирование отключено.

## Галерея

`ArticleGallery` принимает `images: {src, thumbnail?, alt, width?, height?, caption?}[]`
и необязательный group. Размеры относятся к миниатюре. Если thumbnail не задан,
используется src. Пустой массив не выводит контейнер; группа по умолчанию уникальна.
Сетка: 2/3/4/5 колонок на mobile/md/xl/xxl, миниатюры 4:3 с object-fit:cover.
Полноразмерные изображения не обрезаются.
Можно передать массив через gallery в ArticleDetail и заголовок через galleryTitle
либо вставить ArticleGallery прямо в slot в нужном месте текста.

Импорты изображений Astro формируют корректные публичные URL сборки.
При переносе в Битрикс замените их путями CMS, сохраните классы и data-fancybox,
подключайте общие CSS/JS один раз по README.

## Рекомендуемые статьи

На `/article/demo-article/` добавлен RecommendedArticles после содержимого и галереи,
внутри CatalogLayout. После рекомендаций — возврат на `/article/`.
Карточки переиспользуют ArticleCard с variant="recommended"; общие стили сохранены,
новый вариант изолирован в `_recommended-articles.scss` и подключён в main.scss.

API: `<RecommendedArticles articles={items} />` или `recommendedArticles={items}`
в ArticleDetail. Тип RecommendedArticle: title, text?, img?, url?. До четырёх
записей, пустой массив скрывает секцию. Отбор выполняется страницей: первые четыре
уникальные записи assets/articles_list.json, исключая совпадение с заголовком текущей
статьи. Исходный JSON не изменён. Локальные пути сопоставляются с существующим
assets/images/articles через общий articleImage; CMS может передавать публичные пути.
Добавление url к записи включает ссылку заголовка и «Читать далее». Без url
нет ссылок и href="#". Нового клиентского JS нет.

Проверки: npm run check — 0 ошибок, 0 предупреждений, один прежний hint.
npm run build — успешно вне песочницы (внутри ограничение prerender entrypoint),
13 страниц, 508 ссылок проверены. Сохранились прежние Sass deprecations Bootstrap
и предупреждение отсутствующего изображения ProductCard на главной.
Браузер: scripts/test-recommended-articles-browser.mjs, SHOWCASE_BASE_URL задаёт
адрес preview. Chrome с отключённым JS: 1440/1024/768/390/320 px, сетка 4/2/2/1/1,
четыре уникальные записи, все изображения загружены и contain, равная высота в ряду,
нет горизонтального переполнения и фиктивных ссылок, правильное расположение
после галереи и ссылка возврата. Скриншоты: artifacts/recommended-articles/.
Safari/Firefox и CMS-интеграция не проверялись. Сценарий с переданными URL
предусмотрен в компоненте, но в демонстрационном JSON URL отсутствуют.

На этапе разработки заголовки и изображения рекомендаций являются ссылками: без url используется href='#' по запросу заказчика. Переданный url заменяет демонстрационный адрес. «Читать далее» по-прежнему выводится только при реальном URL. Браузерная проверка ожидает восемь ссылок в демонстрационном блоке.
