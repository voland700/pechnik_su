# Фильтр каталога

`CatalogFilter.astro` подключён в существующий slot `filter` на `/category/`, под меню sidebar. Кнопка открытия находится после сортировки. Существующий breakpoint md (768 px) сохранён.

Компонент принимает уникальный `id` и `groups: FilterGroup[]`. Типы находятся в `src/types/catalog-filter.ts`, демонстрационные данные — в `src/data/catalog-filter.ts`. Поддерживаются checkbox, radio и произвольное количество числовых диапазонов. Для radio задайте общий `name` группы; `option.name` позволяет передать индивидуальные имена checkbox из CMS. Доступны checked, disabled, hidden, начальные from/to, step и open числовых групп. Идентификаторы групп и значений должны быть уникальны внутри экземпляра.

SCSS подключён через main.scss, использует токены и существующие Button. Реальные input сохраняют клавиатурную семантику. Списки ограничены 224 px; заголовки не прокручиваются вместе со значениями. Анимации учитывают общее правило prefers-reduced-motion.

main.ts условно загружает модуль catalog-filter.ts, повторная инициализация защищена WeakSet. На mobile единственный DOM-экземпляр фильтра перемещается в dialog, сам dialog переносится в body за пределы скрытого sidebar. На desktop форма возвращается на исходное место. Нативный showModal удерживает фокус и блокирует взаимодействие с фоном; overflow блокирует прокрутку. Закрытие: крестик, overlay, Escape и «Показать»; фокус возвращается на кнопку. Группы независимы; закрытое содержимое inert. Числовые поля нормализуются при change/Enter, бегунки — при input. Reset восстанавливает серверные/демонстрационные начальные значения, не меняя раскрытие групп.

Для Битрикс переносить form, повторяемые section, поля диапазонов, fieldset со значениями, кнопки и dialog. Заменить демонстрационные name/id/value и checked/disabled штатными CONTROL_NAME/CONTROL_ID/HTML_VALUE/CHECKED/DISABLED, добавить скрытые поля и action/method CMS. Сохранить label/for, aria-controls и data-атрибуты интерфейса. Для штатных BX-ползунков заменить внутренность track и исключить демонстрационную синхронизацию диапазонов. Подключить JCSmartFilter и BX.Iblock.SmartFilter отдельно; удалить статическое предотвращение submit и назначить CMS-действия «Показать»/«Сбросить». Не запускать два обработчика раскрытия или два контроллера ползунка одновременно. Исходный reference/template.php не изменён.

Реальной фильтрации, запросов, URL, localStorage, количества результатов и PHP нет. Без JavaScript desktop-разметка и начальный диапазон видны, интерактивное раскрытие и mobile-панель требуют клиентского модуля.

Проверки: npm run check — 0 ошибок/предупреждений, прежний hint в test-featured-products-browser.mjs. npm run build — успешно, 5 страниц, 278 ссылок; запуск вне песочницы из-за ограничения Astro prerender. Прежние предупреждения Bootstrap Sass и отсутствующего изображения на главной сохранены.

`SHOWCASE_BASE_URL=http://127.0.0.1:4322 node scripts/test-catalog-filter-browser.mjs` — headless Chrome: 1440/1024/768/375/320 px, одна форма, начальные состояния, все группы, множественный выбор, ограничение диапазона и клавиатура, reset, внутренний scroll, modal focus, все три способа закрытия, возврат фокуса, отсутствие горизонтального переполнения и ошибок браузера. Снимки и отчёт: artifacts/catalog-filter/. Firefox/Safari и ручной скринридер не проверены. Радиокнопки поддержаны разметкой и нативной логикой, в демонстрации используются только checkbox.
