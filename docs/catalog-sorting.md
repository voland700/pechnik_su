# Панель сортировки каталога

`src/components/catalog/CatalogSorting.astro` — статический компонент без props, JavaScript и формы. Подключён один раз на `/category/` после `CatalogSubcategories`, перед будущими товарами. `CatalogLayout` не изменён; фиктивные товары не добавлены.

Компонент выводит два нативных select с явными label: `sortSelected` (5 вариантов, `default` выбран атрибутом selected) и `sortCount` (12/24/32/44/60/72, selected у 32). Атрибуты name совпадают с ID. Использование: импортировать компонент и добавить `<CatalogSorting />` в default slot CatalogLayout.

Стили `_catalog-sorting.scss` подключены через общий `main.scss`, используют БЭМ и существующие токены цвета, интервалов, типографики, радиуса и высоты поля 44 px. Стандартная стрелка и поведение select сохранены. Есть hover, focus-visible и disabled; поля по умолчанию доступны.

Панель занимает всю ширину контента. До существующего breakpoint sm (576 px) группы идут вертикально; выше используется flex-wrap с выравниванием по краям при наличии места. Поэтому при 768 px с sidebar группы также переносятся. Внутри группы label и select размещаются рядом, при нехватке места подпись переносится над полем. Поле сортировки шириной 14rem ограничено доступной шириной; поле количества имеет естественную ширину. Новых breakpoints нет.

Проверки: `npm run check` — 0 ошибок, 0 предупреждений, одна существующая подсказка в тесте featured products; `npm run build` — 5 страниц, два CSS, 244 ссылки на ресурсы. Сборка выполнена вне песочницы из-за известной ошибки разрешения Astro prerender. Существующие предупреждения Bootstrap Sass и двух отсутствующих изображений ProductCard остаются. Отдельных команд lint/typecheck нет: проверку Astro и TypeScript выполняет `check`.

`SHOWCASE_BASE_URL=http://127.0.0.1:4322 node scripts/test-catalog-section-browser.mjs` (в PowerShell переменная задаётся через `$env:SHOWCASE_BASE_URL`) проверяет панель и существующие категории в headless Chrome с отключённым JS: 1440/1024/768/390/320 px, геометрию, отсутствие переполнения, точные options/value/selected, label, уникальность ID, высоту полей, отсутствие формы и inline-обработчиков, клавиатурный focus-visible и переход Tab между полями. Отчёт и скриншоты — `artifacts/catalog-section/`; снимки sorting-1440 и sorting-320 просмотрены. Firefox/Safari не проверялись.

Для CMS: сохранять классы, ID, name, value и связи label/for; компонент размещать один раз на странице. Начальные значения задаются серверным selected. На текущем этапе изменение выбора меняет только значение нативного поля: сортировка, количество товаров, URL и запросы не меняются. Подключение поведения выполняется отдельным этапом в CMS.

Регрессия: `scripts/test-catalog-browser.mjs` прошёл на том же preview с отключённым JS — 22 категории, изображения, порядок, H1/Breadcrumbs, адаптивность на четырёх ширинах, отсутствие переполнения и ошибок браузера.
