# Демонстрационный Hero Slider с баннерами

Страница: `/hero-showcase/`. Главная `src/pages/index.astro`, данные слайдов и поведение её слайдера сохранены. Разработка и проверка выполнены локально, без публикации.

## Созданные файлы

- `src/pages/hero-showcase.astro` — отдельная демонстрационная страница с общими шапкой и подвалом.
- `src/components/home/hero-slider/HeroShowcase.astro` — композиция существующего слайдера и статичных баннеров.
- `src/components/home/hero-slider/HeroBanner.astro` — переиспользуемый баннер, работающий без JavaScript.
- `src/styles/components/_hero-showcase.scss` и `_hero-banner.scss` — стили в общей SCSS-сборке.
- `assets/slider-banners.json` — четыре записи с исходными текстами из ТЗ. Указанный в задании файл отсутствовал в репозитории.
- `assets/images/banners/{grill,fireplace,stove,sauna}.jpg` — исходные изображения баннеров сайта-референса, соответствующие локальным скриншотам. Их также не было в репозитории.
- `scripts/test-hero-showcase-browser.mjs` — проверка production-страницы через локальный Chrome CDP.
- `artifacts/hero-showcase/` — семь снимков страницы и `results.json` с измерениями 28 состояний.
- Этот отчёт: `docs/hero-showcase.md`.

## Изменённые файлы

- `HeroSlider.astro` — необязательный `variant: 'default' | 'showcase'`, класс варианта и передача скорости через `data-hero-speed`.
- `HeroSlide.astro` — необязательный режим `showcase` с отдельными параметрами слоёв. Значения по умолчанию сохранены.
- `src/scripts/modules/hero-slider.ts` — чтение скорости экземпляра; в новом варианте неактивные слайды получают `inert` уже в начале перехода.
- `src/styles/main.scss` — два новых `@use`.

Остальные изменения, уже находившиеся в рабочем дереве, к этой задаче не относятся.

## Компоненты и данные

```astro
<HeroShowcase slides={sliderData} banners={bannerData} autoplay />
```

`HeroShowcase` принимает `slides`, необязательный массив `banners` и `autoplay` (по умолчанию true). Пустой массив баннеров оставляет слайдер на всю ширину. Меньшее количество баннеров не вызывает ошибки; дополнительные записи выводятся в следующих строках сетки.

`HeroBanner` принимает `name`, `img`, необязательные `text`, `link`, `objectPosition`. Изображение декоративное (`alt=""`), занимает площадь через `object-fit: cover`. Градиент усиливает контраст внизу; заголовок использует тёмный акцентный токен существующей палитры для контраста белого текста. Описание проходит через существующий allowlist HTML, поддерживающий `br`. Размеры, заданные изображению, резервируются композицией с `aspect-ratio`.

```json
{
  "name": "Название категории",
  "text": "Описание <br>с переносом",
  "img": "assets/images/banners/grill.jpg",
  "link": "/подтверждённый-маршрут/"
}
```

Порядок массива определяет порядок баннеров. Реальные маршруты четырёх категорий в проекте не подтверждены, поэтому `link` в демонстрационных данных отсутствует. В этом случае выводится `article`. При безопасном URL выводится ссылка на всю площадь с доступным названием и `focus-visible`; пустые URL, одиночный `#` и небезопасные схемы не создают ссылку. Маршруты стороннего сайта не используются как маршруты Pechnik.su.

У ссылок есть лёгкое увеличение изображения только для устройств с hover и без reduced motion. У статичных баннеров интерактивного эффекта нет. Баннеры находятся вне Swiper и не зависят от его событий или инициализации.

## Адаптивная сетка

DOM единственный: слайдер, затем баннеры 1–4; копий под разные разрешения нет. `order` не используется, стандартный Tab следует DOM. На desktop порядок фокуса: слайдер, левая колонка сверху вниз, правая сверху вниз.

| Ширина | Компоновка |
| --- | --- |
| До 768 px | Слайдер, затем баннеры в одном столбце, пропорция баннеров 16:10 |
| 768–1199 px | Слайдер на обе колонки, затем баннеры 2 × 2 |
| От 1200 px | Колонки `1fr 3.2fr 1fr`, две равные строки; слайдер в центре занимает обе строки |

Gap — 20 px. Высота центрального слайдера на desktop — минимум 448 px и может расти с содержимым; высоты боковых баннеров определяет общая сетка. Контейнеры и breakpoints взяты из Bootstrap-настроек проекта. На мобильном устройстве сохранена вертикальная композиция текста и товарного изображения исходного Hero Slider; она выше референса, поскольку сохраняет все тексты и товарные изображения по ТЗ.

## Swiper и сохранённые функции

Установленный Swiper 14.3.0 уже использовал `EffectFade`, `Parallax`, Navigation, Pagination, A11y, Autoplay. Новая реализация расширяет существующие компоненты и JS-модуль, без дублирующего инициализатора, зависимостей и CDN.

- `effect: 'fade'`, `fadeEffect.crossFade: true` сохранены.
- Для нового варианта скорость 1000 ms вместо исходных 700 ms: более плавное растворение в компактной композиции. Главная остаётся на 700 ms.
- Фон: −1%, 1200 ms.
- Заголовок: X −20 px, opacity 0, 900 ms.
- Описание: X −30 px, opacity 0, 1000 ms.
- Кнопка: Y +15 px, opacity 0, 1100 ms.
- Товарное изображение: X +35 px, opacity 0, scale .95, 1100 ms.
- Fade управляет слайдом, Parallax — вложенными элементами; CSS не меняет их transform. Текст уходящего слайда скрывается в новом варианте, чтобы две рекламные надписи не накладывались при crossFade.
- Reduced motion отключает Parallax, декоративный hover и Autoplay; скорость переключения становится 0. Изменение системной настройки обрабатывается во время работы.

Сохранены четыре исходных слайда, рекламные тексты, поле `backgraund`, фоны, индивидуальное позиционирование, overlay, HTML-описания, условные ссылки заголовка и кнопки, товарные изображения, стрелки, пагинация, touch-навигация Swiper, loop, Autoplay с паузой, пауза при hover/фокусе и скрытии вкладки, клавиатура и защита от повторной инициализации через WeakMap. Клавиатура остаётся локальной, как в исходном модуле: стрелки действуют при фокусе внутри данного слайдера и не переключают другие карусели. Дополнительный глобальный Keyboard-модуль не подключался по этой причине.

Первый фон остаётся eager/high, последующие фоны и товарные изображения — lazy. Баннеры загружаются обычным приоритетом; все четыре небольшие исходные JPEG не получают высокий fetchpriority. Vite выпускает локальные ресурсы с хешами. Для смены формата достаточно заменить пути данных на WebP/AVIF из каталога баннеров.

## Ограничения и Битрикс

Физические touch-устройства, другие браузеры, hover/focus реальных ссылок баннеров и варианты с пустым/неполным набором баннеров отдельно в браузере не тестировались. Touch-механика исходного Swiper сохранена. Отдельные ссылки категорий нужно заполнить после подтверждения URL. Изображения взяты с указанного сайта-референса; перед публичным использованием согласуйте права либо передайте собственные исходники.

В сборке остаются существующие deprecation-сообщения Bootstrap 5.2 / Sass и сообщение ProductCard о постороннем отсутствующем изображении `assets/images/main_XEWTaZkyPl.jpg`; это не ресурс нового блока. В песочнице Astro/Vite не разрешал entrypoint prerender, поэтому production-сборка выполнена с разрешением вне песочницы, без изменений конфигурации.

Для Битрикс переносите HTML из `dist/hero-showcase/index.html`, общий CSS и все связанные JS/asset-файлы одной сборки. Замените массивы серверными данными, сохранив классы, `data-*` атрибуты и последовательность DOM. Поле `backgraund` совместимо с текущими данными. HTML обязательно очищать на сервере по allowlist `p, ul, li, br, span, strong, em`, без обработчиков и произвольных атрибутов; URL и CSS overlay валидировать отдельно. Клиентская инициализация и статичные баннеры не требуют знания структуры инфоблоков. PHP и Bitrix API не добавлены.
