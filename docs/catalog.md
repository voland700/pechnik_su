# Корневой каталог и CatalogLayout

Страница `/catalog/` содержит H1 «Каталог товаров», существующие Breadcrumbs, меню 22 разделов и 22 карточки с 90 дочерними ссылками. Порядок и исходное написание сохранены, включая пробел перед « Напольные листы». Все ссылки меню, изображений, названий и дочерних категорий временно ведут на `#`. Ссылка «Главная» в Breadcrumbs по-прежнему ведёт на `/`.

## Архитектура

- `src/layouts/CatalogLayout.astro`: props `title`, `description`, `heading`, `breadcrumbs`, `navigation`; оборачивает существующим BaseLayout без повторного main/Header/Footer. H1 и Breadcrumbs находятся в полных по ширине `.page-heading` и стандартном `.container` сразу после Header.
- Default slot — произвольное содержимое правой колонки. Именованный slot `filter` передаётся в CatalogSidebar без дополнительных обёрток и пустого места при отсутствии содержимого.
- `src/components/catalog/CatalogSidebar.astro`: получает `CatalogNavigationItem[]`, выводит aside/nav/ul/li/a. Доступное название — «Разделы каталога».
- `CatalogCategories.astro`: получает `items: CatalogCategory[]`, формирует сетку.
- `CatalogCategoryCard.astro`: получает `item`, необязательный `eager`; выводит изображение, H2 и только непустой список дочерних разделов. Ссылки изображения и названия разделены, изображение имеет пустой alt, его ссылка — aria-label с названием.

Страница преобразует неизменённый `showcaseData` в `{ name, url: '#' }[]`. Layout и Sidebar не импортируют данные корневого каталога. Полный самостоятельный `catalogData` хранится в `src/data/catalog.ts`, типы — в `src/types/catalog.ts`.

Пример будущего использования (новый маршрут не создаётся):

```astro
<CatalogLayout
  title="Название — Pechnik.su"
  description="Описание"
  heading="Название"
  breadcrumbs={breadcrumbs}
  navigation={navigation}
>
  <!-- Произвольная разметка категории или товара -->
  <Fragment slot="filter"><!-- Будущий реальный фильтр --></Fragment>
</CatalogLayout>
```

## Дизайн и изображения

Композиция взята из предоставленных desktop/mobile скриншотов и https://pechi-tula.ru/catalog/. Собственные БЭМ-классы, SCSS через общий `main.scss`. Manrope и существующие `--text-base/sm`, `--space-*`, `--color-text/action/surface/border/background`, `--duration-fast`. Нейтральные ссылки меняют цвет и подчёркиваются при hover; глобальный focus-visible сохранён, reduced motion учитывается глобальным правилом.

Границы сетки образуются фоном и зазором 1px, поэтому соседние карточки не удваивают линии. Высота строк определяется содержимым; нет фиксированных высот, обрезания и скрытых дочерних ссылок.

Повторно используется загрузчик `home/category-showcase/images.ts`: import.meta.glob выпускает локальные изображения через Astro/Vite с реальными width/height. Все 22 файла найдены с точным регистром. Изображения показаны через object-fit: contain в квадратной области 64/80/96px в зависимости от ширины. Первые два загружаются eager, остальные lazy, decoding async. Новые зависимости и JS не добавлены.

## Адаптивность

- До 768px Sidebar скрыт CSS, одна колонка карточек.
- 768–991px: Sidebar 224px, одна колонка карточек.
- От 992px: Sidebar и две равные колонки карточек, 11 строк.
- От 1200px Sidebar 240px, изображения 96px.

Во всех вариантах изображение слева, текст справа. minmax(0, 1fr), min-width и overflow-wrap предотвращают переполнение.

## Границы этапа и CMS

Header, Footer, Breadcrumbs, showcaseData и главная не изменены. Категории, товары, фильтры, API и новые дочерние маршруты не созданы. Реальные URL в будущем передаются через `navigation[].url`, `CatalogCategory.url` и необязательную карту `childUrls`, ключи которой совпадают с исходными названиями дочерних разделов. Используется существующий safeUrl; URL автоматически из названий не строятся. Для Битрикс можно заменить источник данных и сохранить HTML-классы и SCSS. Микроразметка не добавлена. Safari/Firefox и ручная проверка скринридером не выполнялись.
