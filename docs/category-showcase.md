# Витрина категорий

Витрина размещена после Hero Slider и перед сохранённым техническим UI Kit. Header, настройки Hero и остальные секции не переработаны. Компонент не содержит script, клиентских обработчиков или дополнительных зависимостей.

## Файлы

Созданы:

- `src/components/home/category-showcase/CategoryShowcase.astro` — секция, H2, контейнер, список и перебор items.
- `src/components/home/category-showcase/CategoryCard.astro` — карточка с одной ссылкой либо обычным div.
- `src/components/home/category-showcase/images.ts` — централизованная обработка путей и размеров изображений.
- `src/types/showcase.ts` — интерфейс ShowcaseItem.
- `src/data/showcase.ts` — 22 категории.
- `src/styles/components/_category-showcase.scss` — оформление в общей SCSS-сборке.
- `src/utils/url.ts` — общая проверка URL, извлечённая из Hero без изменения её поведения.
- `scripts/test-showcase-browser.mjs`, `scripts/fixtures/showcase-check.astro.txt`, `scripts/fixtures/showcase-reference.json` — браузерные проверки, временная страница состояний и снимок исходного порядка.
- `docs/category-showcase.md` — этот отчёт.

Изменены `src/pages/index.astro` (подключение), `src/styles/main.scss` (SCSS), `src/components/home/hero-slider/content.ts` (использует прежнюю проверку URL из общего utils), `README.md` (ссылка на отчёт). Конфигурация сборки и зависимости не менялись.

## Данные и CMS

`<CategoryShowcase items={showcaseData} />`; дополнительный prop `title` по умолчанию «Каталог товаров». Каждый экземпляр получает уникальный heading id. Пустой массив не выводит секцию. CategoryCard принимает `item`.

Интерфейс: `{ name: string; img: string; url?: string }`. Название выводится как текст с экранированием Astro, без HTML. Порядок массива сохраняется. Чтобы добавить категорию, добавить объект в нужное место массива и реальное изображение; ограничений на количество в компоненте нет.

Полного ранее упомянутого массива в доступных исходниках/сообщении не было. Состав, порядок и соответствие имён файлов восстановлены по [секции showcase действующего сайта](https://www.pechnik.su/), сопоставлены со всеми 22 локальными файлами `assets/images/catalog/`; первые две записи совпадают с предоставленным примером. Локальные пути не переименованы. Все url оставлены пустыми: ссылки действующего сайта не переносились без заданных CMS URL.

Для ссылки заполнить url корректным относительным путём либо HTTP(S) URL. Вся карточка станет одним a, изображение и H3 находятся внутри; вложенных ссылок нет. Пустой/отсутствующий URL, одиночный # и небезопасная схема дают обычный div без tabindex, click, cursor:pointer и интерактивного hover. Пример будущих данных: `{ name: 'Печи-камины', img: '/upload/catalog/pechi.jpg', url: '/catalog/pechi-kaminy/' }`. Страницы каталога этим этапом не создаются.

В Битрикс name соответствует NAME раздела, img — URL PICTURE (либо согласованного пользовательского поля), url — SECTION_PAGE_URL. Порядок формируется backend согласно SORT до передачи массива/рендеринга шаблона. PHP и Bitrix API не добавлены. Backend должен валидировать URL, экранировать названия/атрибуты, разрешать доверенные пути изображений. HTML-блок легко заменить циклом разделов, сохранив классы и семантику.

## Сетка и карточки

Стандартный Bootstrap container, CSS Grid: 2 колонки до 768 px, 3 от 768, 4 от 992, 5 от 1200 (в том числе ≥1400). Промежутки 12 px на Mobile, 16 px от MD. Последняя строка не растягивается; пустых элементов нет.

Секция с вертикальными отступами 48 px. Карточки белые, тонкая граница из существующего border-токена, радиус 6 px, внутренние отступы 12/16 px. Изображение сверху в стабильной области 4:3, полное название снизу по центру. Manrope 600, 14 px на Mobile и 16 px от MD. Нет ellipsis, line-clamp, nowrap или ручных br. Карточки одной строки имеют одинаковую высоту, остальные строки растут по содержимому.

Только ссылки получают hover (action-цвет, граница, мягкая тень, подъём 2 px), focus-visible (контрастный outline 3 px), active (без подъёма/тени). Transition 300 мс. Reduced motion отключает transition и transform. Нелинкованные карточки сохраняют нейтральное оформление.

## Изображения и сборка

Все 22 файла существуют; реальные размеры 180×180–300×300, исключения 300×287 и 285×250. `import.meta.glob` с Astro ImageMetadata выпускает оригиналы через Vite с хешированными именами в dist/assets. Нормализация находится в images.ts; input-массив сохраняет исходные пути. Известны реальные width/height, область 4:3 предотвращает сдвиги; img абсолютно вписан через contain/center, без обрезания. Все изображения lazy/async, без высокого приоритета, поскольку витрина следует за Hero. alt пустой: название рядом полностью описывает категорию.

CMS может передать публичный /upload/... либо HTTP(S) адрес, область изображения сохранится даже без метаданных. Отсутствующий локальный файл вызывает предупреждение сборки; карточка сохранит название и область без фиктивного изображения. В текущих данных отсутствующих файлов нет. Автоматическое WebP/AVIF-преобразование и srcset не добавлены; часть исходников 180 px может быть менее резкой на Retina. CDN не используется.

CSS попадает в dist/css/style.css и style.min.css. Нового JS для витрины нет; dist/js/main.js остаётся общей точкой входа. При переносе сохранить dist/assets и общую структуру CSS/JS. Для размещения сайта под префиксом требуется отдельная проверка CMS URL.

## Проверки

Astro check: 0 errors/warnings/hints. Production build и verify:dist успешны: обе CSS-версии и все локальные ресурсы существуют. Сохраняются прежние Sass deprecation warnings от Bootstrap 5.2.

Chrome: 360, 390, 576, 768, 1024, 1200, 1440, 1920 px. Проверены 22 карточки и точный порядок, все изображения, contain, стабильное соотношение 4:3, равная высота карточек строки, полные названия без переполнения/обрезания, отсутствие горизонтальной прокрутки, пять колонок ровно от 1200 px. Временные fixtures проверяют пустой массив, несколько экземпляров, корректный переход единственной ссылки, отсутствие ссылок при пустом/отсутствующем URL, javascript: и #, hover только ссылки, клавиатурный focus-visible, active и reduced motion. Проверяется наличие всей витрины с отключённым JavaScript. Browser errors отсутствуют. Скриншоты и JSON: artifacts/showcase/.

Воспроизведение: `npm run build`, `npm run preview`, `node scripts/test-showcase-browser.mjs`. Для полной проверки состояний временно скопировать scripts/fixtures/showcase-check.astro.txt в src/pages/showcase-check.astro, собрать и запустить тест с SHOWCASE_TEST_FIXTURES=1. Затем удалить временную страницу и пересобрать production. CHROME_PATH позволяет задать путь Chrome; по умолчанию используется установленный Windows Chrome headless.

Ограничения: реальных URL пока нет; Safari/Firefox, экранный диктор и физические устройства не проверялись. Изображения исходного разрешения, без выдуманных замен. Lighthouse и полноценное измерение CLS не выполнялись. Другие секции не добавлялись.
